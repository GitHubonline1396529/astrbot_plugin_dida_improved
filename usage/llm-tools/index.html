    LLM 工具

    插件注册了 LLM Function Tool，可在支持 LLM 的会话中通过自然语言调用，无需用户使用指令。

    工具列表

    工具名称 功能 触发示例
    list_dida_projects 列出所有滴答清单项目 (含收集箱) "我的项目有哪些"
    list_dida_tasks 查询任务列表，支持筛选 "今天有什么任务"、"我的待办有哪些"
    create_dida_task 创建新任务 "帮我创建一个任务"
    complete_dida_task 完成任务 "把任务完成"
    update_dida_task 更新任务的任意字段 (标题、备注、截止日期、优先级等) "把任务备注改成已完成"、"把优先级改为高"
    delete_dida_task 删除任务 "把这个任务删掉"
    reopen_dida_task 重新打开已完成的任务 "把这个已完成的任务重新打开"
    move_dida_task 移动任务到其他项目 "把这个任务移到工作项目"
    get_dida_task_detail 获取单个任务的详细信息 "查看任务详情"
    list_completed_dida_tasks 查询已完成任务 "已完成的任务有哪些"
    get_dida_task_comments 查看任务评论 "看看这个任务有什么评论"
    add_dida_task_comment 添加评论 "给这个任务加一条评论"
    delete_dida_task_comment 删除评论 "删除这条评论"

    使用示例

    下面的示例展示了你在日常学习、工作和生活中可以怎样自然地使用这些工具。对话中加粗部分是 AstrBot 的回复——但请注意，当然了，实际的回复风格会因 LLM 模型而异，以下仅作示意。

    场景一：开启高效的一天

    每天早上，你只需要随口问一句，AstrBot 就能帮你把今天的全局梳理清楚：

    你： 早，帮我看下我的滴答清单，我今天有什么安排？

    AstrBot： (调用 Tools) 你今天有 3 项待办：

    1. 🔴 高优先级 — 提交季度报告 (截止 18:00)
    2. 🟡 中优先级 — 跟产品经理确认需求 (截止 12:00)
    3. 🔵 低优先级 — 整理读书笔记

    报告截止今天下午六点，建议你上午集中精力完成。需要我帮你按优先级排一下今天的日程吗？

    你： 好，把报告安排在上午，需求确认放到下午两点吧。

    AstrBot： (调用 Tools) 已更新「跟产品经理确认需求」的提醒时间为 14:00。上午留出完整时间段给报告，下午开完会时间也比较充裕，安排合理。

    这个过程中，AstrBot 先后调用了 list_dida_tasks(filter="today") 拉取今日任务，又从你的自然语言中理解了日程调整意图，调用了 update_dida_task 更新提醒时间。你全程没有翻看任何列表、没有复制粘贴任何 ID——只是说了一句话。

    • list_dida_tasks 支持 filter="today" 和 filter="unfinished" 两种筛选；
    • 可通过 limit 参数控制返回数量，默认 50，设为 0 则不截断；
    • update_dida_task 内部走的是“获取完整任务 → 合并变更 → 整体提交”的流程，所以可以放心只说想改的字段。

    场景二：从灵感到执行

    设想的灵感来了，随手就能记下来：

    你： 帮我在滴答清单里记一下，下周五之前要把原型设计初稿搞定。

    AstrBot： (调用 Tools) 已创建任务「完成原型设计初稿」，截止日期设为下周五。还有其他需要补充的吗？

    你： 嗯，这个任务优先级高，再帮我加个详情备注——"参考 Figma 社区模板，首页用卡片式布局"。

    AstrBot： (调用 Tools) 已更新任务的优先级为「高」，备注已添加。

    后来，你想起来了更多细节：

    你： 对了，这个原型任务打上「工作」和「紧急」标签，放到「项目 A」里面。

    AstrBot： (调用 Tools) 好的，已将任务移动至项目「项目 A」，并添加了标签「工作, 紧急」。需要我帮你查一下项目 A 的 ID 吗？不用操心，这些细节我都会在后台处理好。

    上面这几轮对话中，AstrBot 依次调用了 create_dida_task、update_dida_task、move_dida_task——你连任务 ID 都没看到，更不用说记了。

    • create_dida_task 支持设置标题 (必填)、备注、优先级 (none/low/medium/high 或 0/1/3/5)、标签 (逗号分隔) 和截止日期 (ISO 格式)；
    • 不指定 project_id 时，默认放入你配置的兜底项目或收集箱；
    • update_dida_task 可更新任意 API 字段：title、content、dueDate、priority、tags、status 等。

    进阶用法：结合联网检索的任务创建

    如果你还配置了 AstrBot 的网络资源检索能力，可以做到更智能的事情——连信息搜集的环节都交给 AI：

    帮我在 Bilibili 上搜一下最近热门的 5~10 分钟的 AI Agent 案例教程视频，把视频标题和 BV 链接整理成列表，写到我的滴答清单里那个「视频学习」任务的备注里。

    或者：

    我计划下半年读沙俄文学。帮我找几本好书——一部大部头长篇，再加三篇篇幅适中的作品。按合理的时间节点，在我的滴答清单里创建下半年的读书任务。

    这些场景中，AstrBot 会先联网检索你需要的信息，再用 create_dida_task 或 update_dida_task 把结果写到任务里——你不用打开浏览器、不用复制粘贴、不用离开聊天窗口。

    场景三：灵活调整任务清单

    项目结构总在变，但整理起来可以很简单：

    你： 我滴答清单里有哪些项目来着？

    AstrBot： (调用 Tools) 你有 4 个项目：

    • 工作
    • 学习
    • 生活
    • 收集箱 (Inbox)

    你： 把「整理 Go 语言笔记」这个任务从收集箱移到学习项目下。

    AstrBot： (调用 Tools) 已移动任务「整理 Go 语言笔记」到「学习」项目。

    你： 对了，那个「试用 Notion AI」的任务过期了，帮我删掉吧。

    AstrBot： (调用 Tools) 已删除任务「试用 Notion AI」。

    你： 等等，我昨天手滑把「买生日礼物」勾掉了，其实还没买……

    AstrBot： (调用 Tools) 已重新打开任务「买生日礼物」，现在它回到你的待办列表中了。

    这里用到了四个工具：list_dida_projects 查看项目 → move_dida_task 移动任务 → delete_dida_task 删除 → reopen_dida_task 重新打开。每个操作都是你随口一句话，AstrBot 自动找到了正确的任务和项目。

    • move_dida_task 需要源项目 ID 和目标项目 ID，但 LLM 会通过之前的项目列表查询自动帮你匹配；
    • delete_dida_task 是永久删除，不可恢复，请谨慎操作；
    • reopen_dida_task 将已完成任务的状态重置为未完成。

    场景四：收尾与复盘

    任务做完了，顺手标记：

    你： 原型设计搞定了，帮我把那个滴答清单里的任务勾掉。

    AstrBot： (调用 Tools) 已完成任务「完成原型设计初稿」。干得漂亮！🎉

    到了写周报的时候：

    你： 帮我看看我的滴答清单，这周完成了哪些事？

    AstrBot： (调用 Tools) 这周你完成了 8 项任务，按项目分布如下：

    • 🏢 工作：5 项 (原型设计、需求文档、代码审查、会议记录、周报)
    • 📚 学习：2 项 (Go 语言笔记、设计模式第三章)
    • 🏠 生活：1 项 (买生日礼物)

    需要我把清单发给你贴到周报里吗？

    • complete_dida_task 标记任务为已完成状态；
    • list_completed_dida_tasks 支持按项目 ID (逗号分隔)、时间范围 (ISO 格式的 start_date / end_date) 和 limit 筛选；
    • 不传时间范围时，默认返回近期所有已完成任务。

    场景五：协作沟通

    在团队项目中和同事讨论任务，也可以直接在聊天里完成：

    你： 看看滴答清单里「产品需求文档」那个任务有什么评论？

    AstrBot： (调用 Tools) 任务「产品需求文档」有 2 条评论： 1. 小张：第三节的交互流程需要补充过渡动画说明 2. 李姐：数据看板的原型我周四前给到

    你： 帮我回复一下小张：收到，我已经在 Figma 里加上了。

    AstrBot： (调用 Tools) 已添加评论：「收到，我已经在 Figma 里加上了。」

    你： 李姐那条评论的内容已经落实了，删掉吧。

    AstrBot： (调用 Tools) 已删除李姐的评论。

    全部在一个对话窗口里完成，不用在滴答清单和聊天工具之间来回切换。

    • get_dida_task_comments 查看指定任务的所有评论；
    • add_dida_task_comment 添加新评论；
    • delete_dida_task_comment 删除指定评论 (永久删除，不可恢复)。

    该场景并未实际测试过

    其实我也不知道这个使用场景在实际工作中是什么样子的，因为我并没有在工作中跟人协作使用过滴答清单。如果因为乱删同事的评论被殴打请不要责怪开发者。

    场景六：深度检索

    有时你需要查看某个任务的完整信息：

    你： 帮我看看滴答清单里那个「性能优化方案」任务的详情。

    AstrBot： (调用 Tools) 📋 任务详情：

    • 标题：性能优化方案
    • 项目：工作
    • 截止日期：2026-08-01 18:00
    • 优先级：高
    • 标签：后端, 优化
    • 备注：参考上一季度的压测报告，重点优化数据库查询和缓存策略

    如果想看看还有哪些没做完的事：

    你： 我最近太忙了，看看滴答清单里还有哪些事拖着没做？

    AstrBot： (调用 Tools) 你还有 12 项未完成的任务。最紧急的几项：

    1. 🔴 高 — 性能优化方案 (后天截止)
    2. 🔴 高 — 季度报告 (今天 18:00 截止！)
    3. 🟡 中 — 跟财务对账 (已逾期 2 天)

    需要我帮你按优先级排一下接下来的时间吗？

    • get_dida_task_detail 返回单个任务的完整信息，需要任务 ID 和所属项目 ID，LLM 会自动匹配；
    • list_dida_tasks(filter="unfinished") 列出所有未完成任务，支持 limit 参数。
